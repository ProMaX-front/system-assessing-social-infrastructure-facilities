# Геоинформационная система оценки обеспеченности социальной инфраструктурой

Тема проекта: **«Разработка геоинформационной системы оценки обеспеченности урбанизированной территории объектами социальной инфраструктуры»**.

## Технологический стек

- React + TypeScript + MapLibre GL JS
- Django + Django REST Framework + GeoDjango
- PostgreSQL 16 + PostGIS
- PyOsmium
- Osmium Tool
- Docker Compose

## Локальный запуск

```bash
git pull
bash start-local.sh
```

После запуска:

- пользовательский интерфейс: http://localhost:5173
- API: http://localhost:8000/api
- Django Admin: http://localhost:8000/admin
- логин локального стенда: `pavel`
- пароль локального стенда: `12345678`

## База геоданных

PostgreSQL/PostGIS используется не только как прикладная БД, но и как локальное хранилище пространственных данных OpenStreetMap.

Основные таблицы:

### `core_roadnode`

Вершины транспортного графа OSM.

Хранит:

- OSM ID вершины;
- координаты;
- признак участия в пешеходном графе;
- признак участия в автомобильном графе;
- ссылку на запуск импорта.

### `core_roadedge`

Унифицированные рёбра транспортной сети.

Одна геометрия дороги не дублируется в двух таблицах. На её основе формируются два логических графа:

- **пешеходный граф** — `walkable = true`;
- **автомобильный граф** — `drivable = true`.

Для ребра хранятся:

- начальная и конечная вершина;
- геометрия LineString;
- длина в метрах;
- `highway`;
- наименование;
- покрытие;
- ограничения `access`, `foot`, `motor_vehicle`;
- разрешённые направления движения отдельно для пешеходов и автомобилей;
- признаки моста и тоннеля;
- исходные OSM-теги.

### `core_osmbuilding`

Полный реестр геометрий зданий OSM в исследуемой территории.

Хранит:

- OSM ID и тип объекта;
- Polygon/MultiPolygon здания;
- репрезентативную точку;
- `building=*`;
- адрес и название;
- исходные OSM-теги;
- категорию социальной инфраструктуры, если она определена.

Если здание имеет только `building=yes`, категория дополнительно определяется пространственно:

1. по нахождению здания внутри территории школы, больницы, детского сада и т. п.;
2. по нахождению точечного OSM-объекта инфраструктуры внутри здания.

### `core_socialobject`

Реестр объектов социальной инфраструктуры.

Поддерживаются категории:

- школы;
- детские сады;
- колледжи и техникумы;
- вузы;
- поликлиники и амбулатории;
- больницы;
- аптеки;
- магазины;
- остановки общественного транспорта;
- спортивные объекты;
- объекты культуры;
- объекты социального обслуживания.

Для объекта хранится точка, используемая при пространственном анализе, а при наличии — полная Polygon/MultiPolygon-геометрия.

### `core_osmimportrun`

Журнал синхронизации с OSM:

- источник;
- дата исходных данных;
- дата и состояние импорта;
- количество вершин;
- количество рёбер;
- количество пешеходных и автомобильных рёбер;
- количество зданий;
- количество объектов инфраструктуры;
- текст ошибки при неуспешном импорте.

## Полная загрузка данных OpenStreetMap

Исходные данные берутся из актуального PBF-экстракта Уральского федерального округа Geofabrik.

Перед импортом система получает административную геометрию Тюменской области из OpenStreetMap, после чего Osmium формирует отдельный региональный PBF. Это исключает загрузку объектов соседних субъектов в рабочую БД.

Для первичной полной загрузки:

```bash
git pull
bash import-tyumen-osm.sh
```

Скрипт автоматически:

1. пересобирает backend с Osmium Tool;
2. применяет миграции PostgreSQL/PostGIS;
3. загружает свежий PBF Уральского федерального округа;
4. получает геометрию Тюменской области;
5. формирует региональный PBF;
6. импортирует автомобильный граф;
7. импортирует пешеходный граф;
8. импортирует все здания;
9. импортирует объекты социальной инфраструктуры;
10. выполняет пространственную классификацию зданий;
11. выводит контрольную статистику.

Исходные файлы сохраняются в `data/osm/` и не попадают в Git.

После импорта проверить БД отдельно можно командой:

```bash
docker compose exec -T backend python manage.py osm_status
```

## Использование OSM

Картографическая подложка и исходные данные OpenStreetMap используются с указанием авторства OpenStreetMap contributors.

Для публичного промышленного развёртывания необходимо отдельно настроить собственный или допустимый production-провайдер тайлов, HTTPS, защищённые учётные данные и регулярное обновление OSM-данных.
